# ⏱️ 기상 · 퇴근시간 맞히기

하루에 두 판. 출제자의 **기상시간**(오전)과 **퇴근시간**(오후)을 초 단위까지 맞히는
모바일 웹 게임. 정답에 가까울수록 점수를 받고, 점수 합계가 누적돼 랭킹에 반영됩니다.

두 게임은 **하단 탭바에 나란히** 있어서 시간이 지나도 양쪽을 다 볼 수 있습니다.

Cloudflare **Workers (정적 에셋) + D1** 로만 동작합니다. 전부 무료 티어 안에서 돌아가고,
빌드 도구 없이 순수 HTML / CSS / JS 로 되어 있습니다.

---

## 두 게임

| | 🌅 오전 게임 | 🌆 오후 게임 |
|---|---|---|
| 맞히는 것 | 출제자의 **기상시간** | 출제자의 **퇴근시간** |
| 기본 출제자 | `min` | 기존 출제자 그대로 (`siwon`) |
| 정답 기록 | **시간 제한 없음** · 그날 안에는 언제든 · **기상했어요** 버튼을 누른 시각이 정답 | **09:00 ~ 17:59** · 출제자가 시간을 직접 적음 |
| 정답 수정 | 그날 안에는 몇 번이든 다시 기록하거나 지울 수 있음 | 17:59 까지 수정 가능 (기회를 한 번이라도 쓰면 잠김) |
| 예측 마감 | **10:00** | **18:00** |
| 게임 없음 | 날짜가 바뀔 때까지 정답이 기록되지 않았으면 그날은 없던 일 | 18:00 까지 정답을 기록하지 않으면 그날은 없던 일 |
| 점수 | 초까지 정확히 **+100점** / 1분 **+10점** / 3분 **+8점** / 5분 **+6점** / 10분 **+3점** / 30분 **+2점** / 1시간 이내 **+1점** | 초까지 정확히 **+3점** / 60초 **+2점** / 120초 이내 **+1점** |
| 기회 | 없음 (바로 공개) | **있음** — 기회를 다 써야 정답을 공개할 수 있음 |

두 게임은 **회차와 기록을 따로** 셉니다. 랭킹에서는 합쳐서도, 한 게임만 따로도 볼 수 있습니다.

## 기회 (오후 게임)

한 번에 못 맞히면 그날 기회가 영영 사라지는 게임이라, 오후 게임에는 **기회**가 있습니다.
출제자는 정답을 공개하기 전에 **기회 소진하기** 를 눌러 힌트를 한 번씩 흘려 줍니다.

| | |
|---|---|
| 기회를 쓰면 | 그때까지 예측한 사람 중 **정답에 가장 가까운 한 명**에게 하이라이트가 들어감 |
| 아무도 없을 때 | 정답과 **5분 이상** 벌어져 있으면 가장 가까운 사람이라도 아무도 뽑히지 않음 |
| 동점이면 | 먼저 낸 사람이 뽑힘 |
| 참가자는 | 남은 기회를 보고(**"이제 기회는 단 한 번!"**) 마감 전까지 예측을 다시 낼 수 있음 |
| 정답 공개 | **기회를 다 써야** 공개 버튼이 나옴 (예측이 마감된 뒤에는 남은 기회와 상관없이 공개 가능) |
| 횟수 | 운영자가 `/setup` 에서 0 ~ 10번으로 정함 (기본 2번, 0이면 기회 없이 바로 공개) |

> 나가는 것은 "누가 가장 가까운가" 뿐입니다. **오차 값은 아무에게도 내려가지 않습니다** —
> 자기 예측을 아는 사람이 오차까지 알면 정답이 그대로 드러나기 때문입니다.
> 기회를 한 번이라도 쓰면 그 힌트가 이미 나간 뒤라 출제자도 정답을 더는 못 바꿉니다.
> 그날 걸린 기회 수는 정답을 기록하는 순간 그 라운드에 박히므로, 운영자가 도중에
> 설정을 바꿔도 이미 시작된 게임은 흔들리지 않습니다.

## 게임 규칙

| | |
|---|---|
| 참가자 | 플레이어 4명 + 운영자 1명 (각자 계정으로 로그인) |
| 출제자 | 그 게임에서 시간을 맞히는 **대상**. 게임마다 한 명. 자기 게임에는 예측을 낼 수 없고 그 게임 랭킹에도 안 들어감 (**다른 게임에는 평범한 플레이어로 참가**) |
| 운영자 | `admin` 계정 하나. 출제자 지정과 잘못 공개된 회차 되돌리기만 하고 게임에는 참여하지 않음 |
| 예측 | 플레이어는 게임마다 하루 한 번, 시·분·초를 직접 찍어 넣어 **초까지** 예측 |
| 수정 | 마감 전까지 몇 번이든 수정 가능 |
| 정답 기록 | **출제자 본인**이 자기 게임의 정답을 정해진 시간대에 서버에 적어 둠 |
| 정답 비공개 | 기록해 둔 정답은 물론 **정답을 기록했는지 여부까지** 출제자 말고는 아무도 모름 (운영자에게도 안 보임) |
| 정답 공개 | 예측을 낸 사람이 **2명 이상** 모이면 출제자가 공개할 수 있음. 공개하는 즉시 오차·점수 확정 (오후 게임은 기회를 다 쓴 뒤부터) |
| 비공개 | 정답 공개 전에는 **아무에게도** 남의 예측이 보이지 않음 |
| 점수 | 정답에 가까울수록 높은 점수. **배점은 게임마다 다름** (위 표 참고) · 어디에도 안 걸리면 **0점** |
| 동점 | 동점이어도 각자 같은 기준으로 점수를 받음 |
| 1등 | 그날 오차가 가장 작은 사람 (동점이면 공동 1등) |
| 랭킹 | 점수 합계 순, 동점이면 정확히 맞힌 횟수 → 평균 오차 순 |
| 회차 | 정답이 공개돼 정상적으로 끝난 게임만 게임별로 1회차씩 올라감 (기본값 1회차) |
| 게임 없음 | 정답이 기록되지 않은 채 기록 시간이 지나면 **게임 없음** 으로 남고 회차를 올리지 않음 |

닉네임은 한글·영문·숫자 **10글자 이내**, 프로필은 **사진**이나 **한 글자**(이모지 가능)로
각자 `/account` 에서 바꿉니다.

프로필 사진은 휴대폰 앨범(또는 PC의 파일)에서 골라 넣고, **정방형(1:1)으로만** 들어갑니다.
사진을 고르면 정사각형 창이 뜨는데, 사진을 끌어 옮기고 확대해 담을 부분을 직접 고르면
그 부분이 512×512 로 잘려 저장됩니다. 사진을 지우면 다시 프로필 글자가 보입니다.
사진은 참가자 목록·랭킹·지난 기록은 물론 **출제자 자리에도** 함께 나옵니다.

> 예측·정답 입력은 시·분·초 칸에 숫자를 직접 찍어 넣습니다. 모바일 브라우저가 띄우는
> 시계형 선택기는 초를 아예 못 고르거나(안드로이드) 다루기 힘든 휠로만 주는데(iOS),
> 초까지 맞히는 게임이라 그래서는 곤란하기 때문입니다. 칸을 누르면 숫자 키패드가
> 뜨고, 두 자리를 채우면 다음 칸으로 저절로 넘어갑니다.

하루의 기준은 **KST(Asia/Seoul)** 입니다. 서버가 직접 KST 날짜와 시각을 계산하므로
기기의 시간대 설정과 무관하게 모두 같은 라운드·같은 마감 시각을 봅니다.

> 정답을 기록해 두어도 라운드 상태는 공개 전까지 계속 '진행 중' 입니다. 그래서
> 다른 사람 화면에는 출제자가 정답을 넣었는지 여부가 아예 나타나지 않습니다.
> 기록 시간대 안이라면 출제자는 기록을 다시 하거나 지울 수 있습니다.

> 예측이 2명 이상 모이기만 하면 마감 전이라도 공개할 수 있습니다. 반대로 기록해 둔
> 정답을 끝내 공개하지 않은 채 날짜가 바뀌면 그 날짜도 '게임 없음' 으로 굳습니다.

## 화면

| 경로 | 설명 |
|---|---|
| `/login` | 로그인 (미로그인 상태로 다른 페이지에 가면 여기로 보냄) |
| `/` | 지금 시간에 맞는 게임으로 보내 줌 (12시 전이면 오전) |
| `/morning` | 🌅 오전 게임 — 기상시간 맞히기 |
| `/evening` | 🌆 오후 게임 — 퇴근시간 맞히기 |
| `/ranking` | 누적 랭킹(전체 · 오전 · 오후) + 지난 30회차 기록 |
| `/admin` | 운영 — 두 게임 현황과 공개 취소 (운영자만 보이고, 운영자만 접근 가능) |
| `/account` | 프로필 사진·닉네임·프로필 글자 설정 / 비밀번호 변경 / 로그아웃 |
| `/setup` | 운영자 페이지 — 초기 설정(끝나면 스스로 닫힘) · **출제자 지정** · **기회 횟수** · 스키마 업데이트 |

## 처음 배포하기

### 0. 준비

```bash
npm install
npx wrangler login
```

### 1. D1 데이터베이스 만들기

```bash
npm run db:create
```

출력에 나오는 `database_id` 를 `wrangler.toml` 의
`PASTE_YOUR_D1_DATABASE_ID_HERE` 자리에 붙여넣습니다.

### 2. 배포

```bash
npm run deploy
```

처음 배포하면 `https://<프로젝트이름>.<계정>.workers.dev` 주소가 나옵니다.

GitHub 저장소를 Cloudflare 대시보드에 연결해 두었다면 푸시할 때마다 자동 배포됩니다.
이때 실행되는 기본 배포 명령이 `npx wrangler deploy` 인데, 이 저장소가 바로 그 형태라
빌드 설정을 따로 만질 필요가 없습니다. (D1 바인딩은 `wrangler.toml` 에서 읽어 갑니다.)

### 3. 초기 설정 (테이블 + 계정)

배포된 주소의 **`/setup`** 에 들어가서 버튼을 한 번 누르면 끝납니다.
테이블을 만들고 계정 5개를 넣습니다. `wrangler login` 도, 터미널도 필요 없습니다.

| 아이디 | 비밀번호 | 역할 |
|---|---|---|
| `yeseo` | yeseo | 플레이어 |
| `min` | min | **오전 출제자** — 이 사람의 기상시간이 오전 정답 |
| `bin` | bin | 플레이어 |
| `siwon` | siwon | **오후 출제자** — 이 사람의 퇴근시간이 오후 정답 |
| `admin` | admin | **운영자** — 출제자 지정·공개 취소 전용 |

> 출제자도 자기 게임에만 빠집니다. `min` 은 오후 게임에, `siwon` 은 오전 게임에
> 평범한 플레이어로 참가합니다.

계정이 하나라도 생기면 `/setup` 은 스스로 닫혀서 두 번 실행되지 않습니다.
`SETUP_TOKEN` 시크릿을 걸어 두면 `/setup?token=...` 으로 토큰까지 맞아야 실행됩니다.

> 지금 비밀번호는 아이디와 같은 짧은 문자열입니다. 소규모 사내 게임이라 괜찮다면
> 그대로 쓰고, 신경 쓰이면 각자 로그인해서 `/account` 에서 바꾸면 됩니다.

**터미널이 편하다면** 같은 일을 CLI 로도 할 수 있습니다.

```bash
npm run db:init      # 테이블 (IF NOT EXISTS — 여러 번 돌려도 안전)
npm run db:seed      # 계정 5개 (같은 아이디는 덮어쓰므로 비밀번호 재설정에도 씀)
```

이제 `https://내앱.workers.dev` 에서 로그인하면 됩니다. 끝.

### 계정을 나중에 바꾸고 싶다면

**닉네임·프로필·비밀번호를 다시 정하고 싶을 때** — `scripts/generate.mjs` 의 `USERS` 배열을
고친 뒤 다시 생성해서 넣습니다. 같은 아이디는 덮어쓰기 때문에 기록은 그대로 남습니다.

```bash
npm run generate     # schema.sql, seed-users.sql, src/lib/seed.js 를 새로 만든다
npm run db:seed
```

**대화형으로 만들고 싶을 때** — `/api/setup` 엔드포인트를 쓰는 CLI 도 있습니다.
아무나 못 쓰도록 토큰을 먼저 걸어 둡니다.

```bash
npx wrangler secret put SETUP_TOKEN     # 아무 긴 랜덤 문자열
SETUP_TOKEN=방금_넣은_토큰 npm run users -- https://내앱.workers.dev
```

`SETUP_TOKEN` 을 설정하지 않으면 `/api/setup` 은 항상 503 으로 닫혀 있습니다.

## 로컬에서 개발하기

```bash
npm run dev                        # http://localhost:8788
```

그리고 http://localhost:8788/setup 에서 버튼을 누르면 테이블과 계정이 준비됩니다.
CLI 를 쓰고 싶다면 `npm run db:init:local && npm run db:seed:local` 도 됩니다.

`/api/setup` 까지 로컬에서 써 보려면 `cp .dev.vars.example .dev.vars` 로
`SETUP_TOKEN` 을 채운 뒤 `npm run dev` 를 다시 띄우면 됩니다.

## 구조

```
public/                  정적 파일 (Cloudflare 의 assets 레이어가 서빙)
  index.html               지금 시간에 맞는 게임으로 보내는 첫 화면
  morning.html             🌅 오전 게임 (껍데기 · 화면은 js/game-page.js 가 그린다)
  evening.html             🌆 오후 게임 (껍데기 · 같은 스크립트를 쓴다)
  login.html / ranking.html / admin.html / account.html
  setup.html               최초 1회 초기 설정
  css/style.css            모바일 우선 스타일 (다크 테마)
  js/common.js             API 호출, 상단 시계, 탭바, 로그인 가드, 프로필 사진 표시
  js/game-page.js          오전·오후 공용 게임 화면 (예측 · 정답 기록 · 공개)
  js/time-input.js         시·분·초를 숫자 키패드로 찍어 넣는 입력칸
  js/photo-picker.js       앨범에서 고른 사진을 정방형으로 자르는 화면
src/                     Worker (API)
  index.js                 진입점 — 경로/메서드 라우팅
  lib/games.js             오전·오후 게임 정의 (시간대 · 정답 입력 방식 · 기회) — 단일 출처
  lib/config.js            게임별 설정 읽기/쓰기 (지금은 기회 횟수 하나)
  lib/schema.js            테이블 정의 (단일 출처)
  lib/migrate.js           예전 스키마를 지금 모양으로 옮기는 마이그레이션
  lib/seed.js              계정 시드 (해시 포함, 자동 생성됨)
  lib/util.js              응답·시간·닉네임·비밀번호 해싱·세션 헬퍼
  lib/image.js             프로필 사진 검사 (형식·용량·정방형 여부)
  lib/game.js              마감·점수·정답 공개·회차 관리
  lib/setter.js            게임별 출제자 조회 / 지정
  routes/…                 각 엔드포인트
schema.sql               자동 생성됨 (src/lib/schema.js 에서)
seed-users.sql           자동 생성됨 (해시 포함, 평문 없음)
scripts/generate.mjs     위 세 개를 만드는 생성기
scripts/create-users.mjs 계정 생성 / 비밀번호 재설정 CLI
```

요청은 먼저 `public/` 의 정적 파일과 맞춰 보고, 맞는 파일이 없을 때만 Worker 로 넘어갑니다.
그래서 `/login` 은 `public/login.html` 로 이어지고 `/api/*` 만 `src/index.js` 가 처리합니다.

## API

인증은 `HttpOnly` 세션 쿠키로 합니다.

| 메서드 | 경로 | 권한 | 설명 |
|---|---|---|---|
| `POST` | `/api/login` | — | 로그인 |
| `POST` | `/api/logout` | — | 로그아웃 |
| `GET` | `/api/me` | — | 현재 로그인 사용자 (미로그인이면 `user: null`) |
| `GET` | `/api/today` | 로그인 | 오늘 라운드 상태 — 회차·마감 여부 포함 (`?game=morning\|evening`, `?date=YYYY-MM-DD` 로 과거 조회) |
| `POST` | `/api/guess` | 플레이어 | 예측 확정/수정 (`{"game":"evening","time":"18:00:30"}`) |
| `POST` | `/api/answer` | 그 게임의 출제자 | 정답 기록 — 오전은 누른 시각, 오후는 `{"time":…}` (서버에만 남음) |
| `DELETE` | `/api/answer` | 그 게임의 출제자 | 기록해 둔 정답 지우기 (기록 시간대 안에서만) |
| `POST` | `/api/chance` | 그 게임의 출제자 | 기회 한 번 소진 — 가장 가까운 사람 한 명이 드러남 |

| `GET` | `/api/ranking` | 로그인 | 누적 랭킹 (`?game=` 없으면 두 게임 합산) |

| `DELETE` | `/api/admin/round` | 운영자 | 정답 공개 취소 (예측과 기록해 둔 정답은 유지) |
| `POST` | `/api/password` | 로그인 | 본인 비밀번호 변경 |
| `POST` | `/api/profile` | 로그인 | 닉네임 / 프로필 글자 / 프로필 사진 변경 |

| `POST` | `/api/setup` | `SETUP_TOKEN` | 계정 생성 / 비밀번호 재설정 |

| `POST` | `/api/bootstrap` | 계정 0개일 때만 | 테이블 생성 + 계정 5개 |

## 보안 메모

- 비밀번호는 PBKDF2-SHA256 10만 회 + 계정별 랜덤 솔트로 해싱해 저장합니다. 평문은 남지 않습니다.
- 프로필 사진은 화면에서 자른 뒤 보내지만, 서버도 파일 헤더를 직접 읽어 형식(JPG·PNG·WebP)과
  크기(정방형 · 64~1024px · 300KB 이하)를 다시 확인합니다. 사진은 로그인한 사람에게만 보입니다.
- 세션 쿠키는 `HttpOnly` + `SameSite=Lax`, HTTPS 에서는 `Secure` 로 내려갑니다. 유효기간 30일.
- 로그인 실패 시 아이디 존재 여부에 따라 응답 시간이 달라지지 않도록 없는 계정에도 해싱을 수행합니다.
- 비밀번호를 바꾸면 그 계정의 모든 세션이 끊깁니다.
- 정답 공개 전 예측은 서버에서 아예 응답에 담지 않습니다. 프론트에서 가리는 방식이 아닙니다.
- 기회의 결과로 나가는 건 "누가 가장 가까운가" 뿐입니다. 오차 값은 출제자를 포함해
  아무에게도 내려가지 않습니다 — 자기 예측을 아는 사람이 오차를 알면 정답이 드러납니다.
- 출제자가 기록해 둔 정답도 마찬가지입니다. 정답과 "기록했는지 여부" 는 그 게임의 출제자
  본인이 부른 응답에만 담기고, 다른 사람에게는 운영자를 포함해 어떤 흔적도 내려가지 않습니다.
  라운드 상태도 공개 전까지 계속 `open` 이라 상태값으로도 눈치챌 수 없습니다.
- `SETUP_TOKEN` 을 설정하지 않으면 `/api/setup` 은 항상 503 으로 닫혀 있습니다.
- `/api/bootstrap` 은 계정이 하나라도 있으면 409 로 거부하고, 테이블 생성도 전부
  `IF NOT EXISTS` 라 기존 데이터를 지우지 않습니다. `SETUP_TOKEN` 을 걸어 두면
  그 토큰까지 맞아야 실행됩니다.

## 이 게임을 매일 하려면

**오전** — 오전 출제자가 일어나면 `/morning` 에서 **기상했어요** 를 누릅니다. 누른 시각이
그대로 그날의 정답이 되고, 서버에만 남습니다 (누르는 시간에는 제한이 없고, 그날 안에는
다시 누르거나 지울 수 있습니다). 플레이어들이 **10:00** 전까지 예측을 내고,
두 명 이상 모이면 출제자가 **정답 공개하기** 를 눌러 그날 회차를 끝냅니다.

**오후** — 오후 출제자가 09:00 ~ 18:00 사이에 `/evening` 에서 퇴근할 시간을 적어 둡니다.
예측이 두 명 이상 모이면 **기회 소진하기** 를 눌러 힌트를 줍니다. 누를 때마다 그때 정답에
가장 가까운 사람 한 명이 드러나고(5분 이상 벌어져 있으면 아무도 안 나옴), 참가자들은 남은
기회 안에서 예측을 다시 냅니다. 기회를 다 쓰면 **정답 공개하기** 버튼이 나옵니다.

다음 날 KST 00:00 이 지나면 자동으로 새 라운드가 시작되므로, 따로 초기화할 것은 없습니다.
잘못 눌렀다면 기록 시간대 안에서 **다시 기록하기 / 기록 지우기**, 잘못 공개했다면 운영자가
`/admin` 에서 **공개 취소**(예측과 기록은 유지)를 쓰면 됩니다.

마감과 '게임 없음' 처리는 크론 없이, 누군가 페이지를 열 때 서버가 함께 정리합니다.
아무도 안 들어와도 다음에 누가 열든 결과는 같습니다.

## 이미 배포해 둔 앱을 업데이트할 때

**따로 할 일은 없습니다.** 배포하면 첫 요청에서 앱이 알아서 DB 를 지금 모양으로
옮깁니다. 워커 인스턴스마다 한 번만 확인하므로 평소에는 비용이 들지 않고,
옮길 게 없으면 아무 일도 일어나지 않습니다.

옮겨지는 내용은 두 가지입니다.

- **스키마** — 지난 기록을 그대로 가져옵니다 (분 → 초, 점수는 오후 게임 배점으로 다시 계산).
  하루 한 판이던 시절의 기록은 전부 **오후 게임(퇴근시간)** 으로 옮겨지고, 회차 번호도
  그대로 이어집니다.
- **기회** — 오후 게임의 기회 표(`round_chances`)와 설정 표(`game_config`)가 만들어지고,
  `rounds` 에 기회 컬럼이 붙습니다. 지난 회차는 그대로 남습니다.
- **출제자** — 기존 출제자가 그대로 **오후 게임** 출제자가 되고, **오전 게임** 출제자는
  `min` 계정이 있으면 그 계정으로 지정됩니다. 바꾸고 싶으면 `/setup` 에서 게임별로
  다시 지정하면 됩니다.
- **계정** — `admin` 계정이 없으면 만들고(`admin` / `admin`), 기존 운영자는 플레이어로
  내린 뒤 그중 한 명을 오후 출제자로 둡니다. 예전에는 운영자가 곧 출제자였기 때문입니다.

즉 배포 후에는 **`admin` / `admin`** 으로 로그인하면 됩니다. 다만 정답을 넣는 일은
이제 운영자가 아니라 **출제자 본인** 이 합니다.

> 자동으로 만들어지는 운영자 비밀번호는 `admin` 입니다. 첫 로그인 뒤
> `/account` 에서 바꾸는 걸 권합니다.

손으로 돌리고 싶다면 `/setup` 페이지의 **스키마 업데이트 실행** 버튼이나
`curl -X POST https://내앱.workers.dev/api/migrate -H "x-setup-token: ..."` 도 그대로 됩니다.
`/setup` 은 아직 안 옮겨진 게 있으면 무엇이 남았는지도 함께 보여 줍니다.
